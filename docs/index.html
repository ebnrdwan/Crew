v0.1.0 Features

🧭
Phase-Based Workflow
6 phases from strategy to launch. Each phase has dedicated agents, gates, and outputs. Phase tracker in .crew/current-phase.yaml.
🚀
/crew drive
End-to-end product-led feature development: pm-architect → implementation → QA → gap audit. One command, full pipeline.
🔍
/crew gaps
5-phase UI gap audit: inventory → interact → inspect → compare → report. Auto-dispatches fix agents with verification.
📦
/crew deploy
Pre-deployment checklist with auto-remediation. Verifies env, runs health checks, dispatches agents to fix failures.
🌉
Gang Bridge
/crew gang-import brings GO Packages from Gang into the Crew roadmap. /crew gang-escalate sends stalled features back for re-scoring.
🎯
API Contract is Sacred
Zero-tolerance enforcement: docs/api-contract.md is single source of truth. Both ui-engineer and api-engineer must verify alignment before implementation.
🪜
Onboarding Wizard
/crew onboard detects project type (fullstack / frontend / backend / mobile), imports context, audits, and sets the right phase.
🌿
Git Workflow
Feature → task → subtask branching. Merge only on explicit user approval. /crew feature creates branches and tracks progress.
🔌
MCP Setup
/crew setup-mcp configures Jira, Notion, Linear, GitHub, SuperDesign and other MCP servers in one go.
📋
Feature Dashboard
/crew features shows roadmap status, pages, navigation flow, acceptance progress. Filterable by status/epic/priority.
🤖
20 Specialised Agents
No general-purpose agent fallback. Every phase has scoped specialists with clear boundaries — strategy, design, build, quality, launch.
🎨
Multi-Platform UI
One ui-engineer agent handles React, React Native, SwiftUI, and Jetpack Compose. Cross-platform consistency from styled-dsl.yaml.
⏸
Usage-Aware Checkpointing
Stops cleanly at 98% session usage (configurable). Saves a checkpoint, schedules /crew resume for after the rate-limit window resets + 10min buffer. No more half-built features when budget runs out.
🗣
Plain-English Mode
Asks once per technology: "How would you describe your knowledge of {tech}?" When any tech is none/low, all agent dispatches get a PLAIN ENGLISH MODE prefix — explanations match the user's level. Cached in .crew/profile.yaml.
🪜
Hierarchy Mapping
Epic, Sprint, Story, Task all on one GitHub board with no duplicates. One card per shippable unit; epics/sprints become custom fields, tasks become checklist items inside the card. Identity = feature_id.

Differs from Gang's discrete-card model: Gang pushes a card after advise and another after deliver; Crew keeps one card alive across the build. Mapping is configurable in .crew/config.yaml.

Hierarchy · Epic / Sprint / Story / Task

Crew has 4 levels but pushes only one card per shippable unit (story). Epics, sprints, and tasks become metadata — never their own cards. Boards stay readable; hierarchy stays queryable via grouping/filtering.

Crew model
Epic (theme) └─ Sprint (timebox) └─ Story (shippable) └─ Task (impl detail)
GitHub representation
Epic → custom field Sprint → Iteration / field Story → THE CARD Task → checklist in body
No-duplication rule
Identity = feature_id. Cache file .crew/github-cards.yaml tracks which card belongs to which feature on which board. All 6 entry points (/crew feature, /drive, /gang-import, /gaps, phase auto-trigger, manual /push) check the cache first → exists, update; missing, create.
Smart field detection
The sync script auto-detects whether your board's Epic/Sprint fields are Single-select, Iteration, or Text and routes the value accordingly. Use whichever field type your team prefers — Crew adapts. Fields the board doesn't have are silently skipped, never errored.

Full design rationale, worked example, rejected alternatives, and card body skeletons in hierarchy-mapping.md + card-skeletons.md.

Usage-Aware Checkpointing · Auto-Resume

Heavy phases burn tokens fast. Crew estimates each upcoming op against a configurable budget; at 98% session usage (default; tunable) it stops cleanly — saves a checkpoint with the exact next step that was about to run, and schedules /crew resume to fire after the rate-limit window resets + 10min buffer.

≤ 90% — ok
Proceed normally. Budget healthy.
90–98% — warn
Proceed but log; consider lighter dispatch mode.
≥ 98% — stop
Checkpoint + schedule resume + exit gracefully.

Defaults tuned for the Anthropic Max plan (5M tokens / 5h reset window). Reduce max_tokens_per_session to ~1,000,000 for Pro. Idempotent resume (lock file + consumed-checkpoint archival) — same checkpoint can never trigger a second resume. Full doc: references/usage-budget.md.

Plain-English Mode · Per-Tech Knowledge Profile

The first time a technology shows up in a project, Crew asks once: "How would you describe your knowledge of {tech}?" — answer cached forever in .crew/profile.yaml. Never re-asked unless you /crew profile clear {tech}.

None
Plain English for everything
Low
Explain non-obvious choices
Intermediate
Default agent verbosity
High
Terse, idiomatic, expert

When any tech is none/low, all agent dispatches get a PLAIN ENGLISH MODE prefix: spell out acronyms, explain framework patterns, narrate the why. Trades brevity for clarity. Profile is project-scoped — different projects, different levels for the same tech.
