The Problem

Building software with AI
is structurally messy.

One model trying to do everything. Context lost between conversations. The same mistakes repeated across features. No clear handoff between strategy, design, and engineering.

🌀

Context decay

The agent forgets last week's decisions. The model that planned the feature isn't the one that built it.

📉

Quality varies

Some features ship clean, others land broken. Hard to predict which is which until QA — or production.

🔁

Repeats itself

The same bugs, the same anti-patterns, the same questions every cycle. No structural memory.

The Idea

Three structural fixes.

Don't make one agent do everything. Don't communicate through chat. Don't let phases blur.

1

Specialised agents

20 agents, each scoped to one domain. A UX designer doesn't write backend code. An API engineer doesn't make design decisions. Each phase has its own specialists.

2

File-based handoffs

Agents communicate through artifacts (BRD, API contract, styled-DSL, roadmap), not chat. Context survives across conversations because it's written down, not remembered.

3

Phase gates

6 phases from strategy to launch. Nothing moves forward without explicit user approval. No skipped steps. No autonomous decisions on what ships.

When Gang Hasn't Run

Three explicit choices.

/crew drive auto-detects an existing GO Package. When it doesn't find one, you choose how to plan — no silent passthrough.

Recommended

Plan via Crew Phase 1

Dispatch product-strategist + feature-planner to produce vision, personas, KPIs, and a proper roadmap entry. ~30K tokens, ~5 min. Best for non-trivial features.

Fast lane

Skip — use my inputs

Proceed with the description you provided. Drive injects short check-in questions at every dispatch boundary so scope stays tight without an upfront plan.

Pause

Run Gang first

Halt drive cleanly. Run /gang init→deliver separately, then re-run /crew drive — the package is auto-detected.

Usage-Aware Checkpointing

Stop at 98%. Resume at reset.

No more half-built features when the rate limit hits. Crew estimates each upcoming op against your budget; at 98% it stops cleanly, schedules /crew resume for after the window resets + 10min buffer.

≤ 90%

ok

Proceed normally. Budget is healthy. Standard dispatch.

90 – 98%

warn

Proceed but log a warning. Consider lighter dispatch mode if available.

≥ 98%

stop

Save checkpoint with the exact next step. Schedule resume task. Exit gracefully.

# Auto-flow on stop: 1. Write .crew/checkpoints/{ISO}-{feature}.yaml 2. Compute scheduled_resume_at = session_start + 5h + 10min 3. Call mcp__scheduled-tasks__create_scheduled_task 4. Print pause message · exit cleanly
Diagnose & Fix

Investigate. Then fix.

Two commands cover the diagnose → fix lifecycle. Run them stand-alone or chained: investigate ends with a recommendation; /crew fix picks up where the spike left off.

Strategic ≠ technical. Crew does not auto-route to Gang. /crew investigate is for technical only — bugs, perf, integration, architecture. For strategic investigations (retention, churn, market) use /gang directly. Tool choice is yours.
Plain-English Mode

Calibrated to your level.

Asked once per technology: "How would you describe your knowledge of {tech}?" Cached forever in .crew/profile.yaml. Different levels for different projects.

None

Plain English for everything. Spell out acronyms.

Low

Explain non-obvious choices. Narrate the why.

Intermediate

Default agent verbosity. Standard idioms okay.

High

Terse. Idiomatic. Expert. Skip the basics.

When any tech in play is none/low, all agent dispatches get a PLAIN ENGLISH MODE prefix. Trades brevity for clarity. Asked once per tech, cached per-project — a senior on TypeScript at work can be a Python beginner in their side-project. The profile follows the project, not the person.
